## Content

### Context

NEED-0007 により、workspace 種別に応じた persona 注入が求められる。現行は `~/.cursor/lucid-memories/persona/` の global persona のみを注入している。分類は Agent 提案とユーザー承認、後からの override が必要である。

### Decision

persona 注入は **置換ではなく合成** とする。合成順と優先度は次の 3 層とする。

1. **Global persona** — 全 workspace 共通の土台。常に注入対象。
2. **Type template overlay** — confirmed な種別 binding に対応するテンプレート。global に上乗せ。
3. **Workspace overlay** — 個別 workspace 向けの追加方針。任意。type template に上乗せ。

種別 binding が pending の workspace では 2・3 層を注入しない。トークン予算超過時は **workspace overlay → type template → global の順で省略** せず、**workspace overlay → type template の順で省略** し、global persona は可能な限り保持する。

分類提案は Agent が行い、binding 確定はユーザー承認（confirm）必須とする。override は binding と workspace overlay の両方に適用可能とする。

### Consequences

- global persona の自己学習（`persona_candidates`）は引き続き user スコープのみとし、workspace 局所指示は type/workspace overlay へ分離できる。
- hook の `beforeSubmitPrompt` は workspace root を解決し、confirmed binding を参照して合成注入文を返す（`persona.get_injection(workspace_root=...)` → `workspace_persona.compose_injection`）。
- 永続化は SQLite（`workspace_persona_bindings`, `workspace_persona_overlays`, `workspace_persona_binding_events`）と種別テンプレート JSON で実装済み。CLI / MCP `persona_workspace` で操作可能。
- `tests/test_workspace_persona.py` が pending 時 global のみ注入、confirmed 後 3 層合成、hook 連携を検証している。
- ダッシュボードでの binding / overlay 編集 UI は未実装。運用は CLI / MCP 経由。
