## Content

### Context

`core/api.py` は MCP・CLI・Hook・Dashboard が共有する公開ファサードだが、約 4,300 行・関数約 97 個に肥大化している。`memory.py`・`graph.py`・`retrieval.py`・`persona.py` など下位モジュールは存在する一方、ユースケースオーケストレーションが `api.py` に集中し、変更波及とテストの読みづらさが増している。

### Decision

`core/api.py` は **互換ファサード** として残し、実装を次のドメイン境界モジュールへ段階的に移す。各フェーズは既存テストが通る単位で land する。

| 新モジュール | 移す責務（現 `api.py` の関数群） |
|---|---|
| `core/knowledge_ops.py` | `remember`, `search`, `list_knowledge`, `archive`, `_sync_knowledge_fts`, `_knowledge_text`, FTS 同期 |
| `core/embedding_ops.py` | `index_embedding`, `semantic_search`, `embedding_status`, `backfill_embeddings`, `_embedding_text` |
| `core/session_ops.py` | `ensure_session`, `persist_session_summary`, `heartbeat`, `bind_current_session`, `unbind_current_session`, `save_prompt`, `bind_pending_prompt`, `last_prompt`, `last_turn`, `generation_changed` |
| `core/usage_ops.py` | `record_usage`, `record_mcp_usage`, `record_activity`, `load_artifact`, usage/activity ヘルパ |
| `core/job_ops.py` | `job_start`, `job_update`, `job_done`, `acquire_lease`, `release_leases_for_session`, `job_claim`, `_append_job_event` |
| `core/pack_ops.py` | `load`, `_load_pack_items`, `snapshot_compact`, `reload`, `save_handoff`, `load_handoff`, `post_notice`, `_add_pack_item` |
| `core/retrieval_ops.py` | `collect_retrieval`, `log_retrieval`, `retrieval_gaps`, `improve_retrieval`, `improve_from_logs`, `measure_retrieval`, `eval_retrieval`, `_flatten_retrieval`, digest 用 retrieval 連携 |
| `core/identity_ops.py` | `whoami`, `status`, `_effective_job_status`, `_bound_current_session` |
| `core/dashboard_ops.py` | `dashboard_graph` と関連ヘルパ（`_dashboard_*`, `_dashboard_temperature`） |

**移さないもの**

- `persona_workspace` は既に `workspace_persona.py` を委譲している。`persona_candidates` 等は `persona.py` 側へ寄せる。
- `graph.link` / `graph.recall` 等の Map 操作は `graph.py` に留める（`api.py` は呼び出しのみ）。

**移行ルール**

1. 関数シグネチャと戻り値 JSON 形状は変更しない（MCP / Hook 契約維持）。
2. `api.py` は `from .knowledge_ops import remember as remember` 形式の再エクスポートを残し、entrypoints の import パスは当面 `core.api` のまま。
3. 1 モジュールずつ PR 単位で移し、各 PR で `tests/` を実行する。
4. 移行完了後、`api.py` は 200 行未満の再エクスポート＋薄い合成（`digest_text` 等の横断ユースケースのみ）を目標とする。

### Consequences

- 読者はドメイン単位で変更箇所を特定できる。新機能は該当 `*_ops.py` に追加し、`api.py` にロジックを書かない。
- 短期的にはファイル数が増えるが、各ファイルは 300〜600 行程度に収まる見込み。
- `web/backend/repositories.py` の二重実装は本 ADR の範囲外。Dashboard 側は別途 `core.*_ops` を呼ぶリファクタを検討する。
