## Content

### Context

lucid-memories の運用ダッシュボード（React + TypeScript + Vite によるグラフィカル運用コンソール）は、従来外部リポジトリ（`Projects/lucid-memories-dashboard`）として分離管理されていた。

しかし、このダッシュボードは本質的に lucid-memories のローカル記憶基盤（SQLite / Ladybug DB）のセッション、ジョブ、想起グラフ、メモリ・知識候補などを読み取り・可視化するための専用ツールであり、外部リポジトリとして分離する意味や独立運用する合理性が乏しかった。また、外部プロジェクトへの依存により、ドキュメント・テストケースの参照パスが外部パス（`Projects/lucid-memories-dashboard/frontend`）となり、一貫したモノレポ・完全自己完結型パッケージとしての運用を妨げていた。

### Decision

外部リポジトリに分離されていた運用ダッシュボード一式（TypeScript/React フロントエンドおよび Python API サーバー機能）を、本 `lucid-memories` リポジトリへ完全に内包・集約する。

1. **フロントエンドの配置**:
   - リポジトリルート配下に `frontend/` を配置し、React + TypeScript + Vite + Sonner のソースコード、アセット、テスト、依存定義（`package.json`, `tsconfig.json` 等）を一元管理する。
2. **バックエンドサーバー機能の集約**:
   - `src/lucid_memories/web/` 配下にダッシュボードの HTTP API サーバー機能（サービス・リポジトリ・クエリ処理）を統合し、`lucid-memories dashboard` コマンドおよび Python モジュールから直接起動可能とする。
   - ビルド済み成果物（`frontend/dist/`）を静的ファイルとして自動配信し、Node.js が存在しない環境や通常実行時でも単一コマンドでリッチなダッシュボードが立ち上がる構造とする。
3. **テスト・ドキュメントの自己完結**:
   - `docs/test-cases/TC-0009.md` などの参照先を内部パス（`frontend/`）へ是正し、リポジトリ単体ですべてのビルド・テスト・検証（`npm run typecheck`, `npm test`, `python -m unittest`）が完結するようにする。

### Consequences

- 外部リポジトリへの依存が完全に解消され、`lucid-memories` リポジトリ単体でコア機能・CLI・フック・MCP サーバー・運用ダッシュボードのすべてが自己完結する。
- `frontend/` での独立した UI 開発・Hot Reload（Vite dev）と、Python コア側での一体型パッケージング（`lucid-memories dashboard`）の両立が可能となる。
- 別リポジトリの二重管理やパス参照の不整合がなくなり、開発・メンテナンスコストが大幅に低減する。
