## Content

### Context

`ARCHITECTURE.md` と `DSN-0008` は「Ladybug プライマリ + SQLite `ontology_edges` フォールバック」と記述していた。2026-09-14 のコード調査で、実態は次のとおり判明した。

- ノード索引: SQLite `ontology_nodes` + FTS
- エッジ・探索: Ladybug DB `map.lbdb` の Cypher（`link`, `recall`, `confirm`, `forbid`）
- `ontology_edges` テーブルは未実装（設計のみ）
- `link` / `confirm` / `forbid` は Ladybug 必須。`recall` は `map.lbdb` 不在時に空結果を返す

### Decision

**案 A を採用する。Ladybug は Map 操作の必須依存とし、SQLite エッジフォールバックは実装しない。**

ハイブリッド構成は次の役割分担で明文化する。

| 層 | ストア | 責務 |
|---|---|---|
| ノード正本 | SQLite `ontology_nodes` | ノードメタデータ、FTS 解決、workspace スコープ |
| エッジ正本 | Ladybug `map.lbdb` | TRIGGERS / USES / ABOUT / IN_CONTEXT / RELATED / FORBIDS |
| 書き込み | 両方 | ノード作成・更新時に SQLite と Ladybug を同期 |

`pip install -e .` により `ladybug>=0.20.0` は必須依存。Windows は `ladybug_runtime.py` の OpenSSL DLL シムに依存する。

`DSN-0008` のフォールバック設計は supersede する。

### Consequences

- `ARCHITECTURE.md` のフォールバック記述を削除し、本構成に合わせて更新する。
- Ladybug 未導入・`map.lbdb` 欠損時は Map 機能（`link`, `recall`, `confirm`）が動作しない。Knowledge の FTS 検索は独立して動作する。
- `map_status()` が `graph: false` の場合、ダッシュボードと MCP で明示的に警告表示することが望ましい（将来 REQ）。
- SQLite 一本化やレプリカ方式が必要になった場合は別 ADR で再検討する。
