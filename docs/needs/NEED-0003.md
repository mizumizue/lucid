## Content

### Background

lucid-memories の Web ダッシュボードでは、会話（Conversation）、想起イベント（Retrieval）、および想起された記憶やマップ（Memory / Map）の関係性を 3 列のグラフ構造として可視化している。エージェントが 1 回のプロンプトで複数のツールを実行する際、文脈維持のためにツール呼び出しごとに想起リクエストが内部で発行・記録される。

### Problem

現状の想起グラフ生成処理は、発行された個別の想起リクエストごとに 1 つの Retrieval ノードを作成している。このため、1 つのユーザープロンプトに対して複数回のツール実行が行われると、中央列に全く同じプロンプト名の想起ノードが縦に何個も重複して並び、ユーザーにとって「同じ記憶が重複して登録されている」かのような誤解を与え、グラフ全体の視認性と一覧性を著しく損ねている。

### Desired Outcome

同一会話かつ同一プロンプト（または同一クエリ）に属する想起ノードが 1 つにマージ・集約され、実行回数がバッジやカウント値として視覚的に表現されることで、無駄な重複表示を排除し、直感的で整理された想起関係が把握できるようになること。
