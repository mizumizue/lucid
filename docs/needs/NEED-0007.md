## Content

### Background

lucid-memories は全ワークスペース共通の `[global persona]` をプロンプト送信前に自動注入している。一方、利用者はアプリ開発、インフラ、メモ、研究など性質の異なる複数ワークスペースを並行利用しており、共通方針に加えて種別や個別 workspace に適した振る舞いをエージェントへ与えたい。

### Problem

現状の persona は workspace 非依存の 1 本のみであり、workspace を切り替えても注入内容は変わらない。`.cursor/rules/` は repo 単位の静的ルールに留まり、種別テンプレートや Agent による初回分類結果を persona 注入へ反映する仕組みがない。誤分類をそのまま確定すると振る舞いがずれるため、分類結果の承認と後からの修正手段も必要である。

### Desired Outcome

Agent が workspace を種別（および必要なら個別 workspace）へ分類し、ユーザー承認後に binding を確定できる。確定後は `[global persona]` を土台に種別テンプレートと workspace 固有 overlay を合成し、トークン予算内でプロンプトへ注入される。ユーザーは後から種別 binding や overlay を override できる。
