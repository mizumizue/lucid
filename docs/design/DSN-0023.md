## Content

### Decision

新しい永続化テーブルは作らず、既存の `usage_events` に `event_type = mcp` の行を追加する。MCP サーバーのツールディスパッチ完了時に結果 JSON の見積もりトークンを記録し、ダッシュボード集計は `event_type` でモデル Usage と分離する。

### Structure

- 記録口: MCP ツールディスパッチが結果を返す直前に、会話識別子（引数または現行セッション束縛）・生成識別子・ツール名・結果本文トークンを書く。
- 行の中身: `total_tokens` / `output_tokens` に結果本文の見積もり、`input_text` にツール名、`metadata_json` に `source=mcp` と予算・内部トークン数。
- 読み出し: 概要・日次・セッション詳細は `event_type = mcp` だけを MCP 利用量とし、モデル Usage はそれ以外だけを合算する。`event_type` 列が無い旧スキーマでは MCP を未計測として扱う。

### Data Flow

```text
[MCP tools/call]
     │
     ▼
[ツール実行結果]
     │
     ├─► 呼び出し元へ JSON 本文を返す
     └─► usage_events (event_type=mcp) へ見積もりトークンを記録
              │
              ▼
[ダッシュボード API]
     ├─ overview.mcp / usage（mcp 除外）
     ├─ analytics/daily の mcp_calls, mcp_tokens
     └─ session.relationships.mcp
```

### Trade-offs

- 専用テーブルを増やさず既存 Usage 行を流用するため、読み出し側で必ず種別フィルタが必要になる。フィルタ漏れは出力トークン合計を汚染するが、列追加や新テーブルより変更面は小さい。
- フックの MCP 完了イベントは呼び出し有無の活動記録に留め、トークン量の正本は MCP サーバーが返す本文とする。フック側に結果本文が無いため二重計上を避ける。
