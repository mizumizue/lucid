## Content

### Decision

複数エージェントやサブエージェントが同一リソース（ファイルやタスク）に同時に変更を加えるのを防止するため、SQLite の `leases` テーブルを用いた有効期限（TTL）付きの分散リースロック機構を採用する。

### Structure

- `core.api.acquire_lease` / `release_lease`: リース獲得・解放のファサード関数。
- `leases` テーブル: `resource`, `holder`, `expires_at`, `created_at` を主キーおよび一意制約で管理。
- トランザクション境界: 獲得処理を SQLite の `write_tx` 内で不可分に実行。

### Data Flow

1. エージェントが対象リソース名と有効期限（既定300秒）を指定して `acquire_lease` を呼び出す。
2. システムは `leases` テーブルを照会し、該当リソースの既存レコードが存在しないか、または `expires_at < 現在時刻`（失効済み）であるか確認する。
3. 条件を満たす場合、新しい保持者と延長された `expires_at` でレコードを挿入または更新し、成功を返す。
4. 条件を満たさず他者が保持中の場合は競合エラー（保持者と失効予定時刻）を返して処理を中断させる。
5. 作業完了時にエージェントが `release_lease` を呼び出してレコードを削除する。

### Trade-offs

- 外部の分散ロックサーバ（Redis, ZooKeeper等）を必要とせず、SQLite だけで確実なプロセス間排他制御を実現できる。
- プロセスがクラッシュした場合でも TTL による自動失効があるため、恒久的なデッドロックを防止できる。
