## Content

### Decision

知識の永続化と高速全文検索の基盤として SQLite の WAL（Write-Ahead Logging）モードおよび FTS5 仮想テーブルを採用し、複数プロセスからの並行読み込みと整合性のある単一書き込みトランザクションを担保する。

### Structure

- `storage.db`: SQLite 接続管理、WAL モード設定（`PRAGMA journal_mode=WAL`）、排他書き込みコンテキストマネージャ（`write_tx`）。
- `knowledge` テーブル: 知識メタデータ、タイトル、本文（インライン制限内）、およびステータスを保持。
- `knowledge_fts` テーブル: FTS5 仮想テーブル。タイトル・本文・タグを対象に高速な全文検索インデックスを提供。
- `core.api`: トランザクション境界を制御し、知識挿入と FTS 更新を不可分に実行。

### Data Flow

1. クライアントが知識登録を要求すると、`core.api` が `storage.db.write_tx` を開始する。
2. `knowledge` テーブルにレコードを挿入し、同時に `knowledge_fts` へインデックスレコードを書き込む。
3. トランザクションがコミットされ、WAL ログへ先行記録された後に成功応答が返却される。
4. 全文検索時は `knowledge_fts` を走査し、ランク順に `knowledge` の実体を取得して返す。

### Trade-offs

- WAL モードにより MCP サーバと Hook IPC からの並行読み出しがブロックされない利点がある。
- 単一ファイル SQLite であるため、並行書き込みの頻度が高い状況では一時的なビジーリトライが発生し得る。
