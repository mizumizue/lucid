## Content

### Decision

ベクトル埋め込み生成にはローカルの Ollama（`nomic-embed-text` モデル、768次元）を使用し、ベクトルデータは外部ベクトルDBを立てずに SQLite の `embeddings` テーブルへリトルエンディアン float32 BLOB として格納してインメモリでコサイン類似度を走査・計算する。

### Structure

- `runtime.embedding`: Ollama REST API と通信し、テキストから 768 次元の浮動小数点配列を取得するアダプタ。
- `embeddings` テーブル: `entity_type`, `entity_id`, `model`, `dimensions`, `vector`（BLOB）を保持。
- `core.retrieval`: SQLite から対象ベクトルを一括ロードし、クエリベクトルとのドット積・コサイン類似度を高速計算してランキングする。

### Data Flow

1. 検索クエリ文字列を `runtime.embedding` が受け取り、ローカル Ollama からクエリベクトルを生成する。
2. `core.retrieval` が `embeddings` テーブルから指定モデル・スコープの全ベクトル BLOB を取得する。
3. インメモリでコサイン類似度を一括計算し、指定された `min_score` 以上の知識をスコア降順でソートする。
4. 一致した知識詳細を SQLite から取得してクライアントへ返却する。

### Trade-offs

- 専用のベクトルデータベース（Chroma, Qdrant等）を導入せず、依存関係を極小化してローカル完結を実現できる。
- 知識件数が数万件を超える大規模環境では全件スキャンによる計算時間が増加するため、インメモリキャッシュやインデックス最適化の検討が必要となる。
