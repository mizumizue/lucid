## Content

### Decision

ナレッジグラフ基盤として、プライマリに Ladybug DB（組み込み Cypher グラフエンジン）を採用しつつ、ライブラリ未導入環境や障害時には SQLite 内のオントロジー表へ透過的にフォールバックするハイブリッド構造とする。

### Structure

- `runtime.ladybug_runtime`: ネイティブ Ladybug DB 接続を管理し、Cypher クエリ（MATCH, MERGE）を実行するプライマリアダプタ。
- `storage.db`: `ontology_nodes` および `ontology_edges` テーブルを定義したフォールバック用リレーショナルエンジン。
- `core.graph`: グラフ操作の共通インターフェースを提供し、Ladybug 利用可否を自動検出して処理を振り分けるファサード。

### Data Flow

1. グラフの登録や検索要求（`link`, `recall` 等）が `core.graph` に届く。
2. `core.graph` は Ladybug DB の利用可否をチェックする。
3. 利用可能な場合は `runtime.ladybug_runtime` 経由で Cypher クエリを実行し、高速なグラフ探索を行う。
4. 利用不可の場合は `storage.db` のオントロジーテーブルに対して SQL 再帰クエリまたは JOIN を実行して同一の結果を構築する。

### Trade-offs

- ネイティブグラフエンジンの高速なパス探索能力を活用しつつ、環境構築のハードルを下げてポータビリティを確保できる。
- グラフスキーマとリレーショナルテーブルの両方に対するクエリ生成・データ変換ロジックを保守するコストが発生する。
