## Content

### Decision

ADR-0006 に基づき、ルート直下に散在していたセットアップランナー（`setup.sh`, `setup.ps1`）および `scripts/setup.py` を、セットアップ自律化スキルの資産として `skills/setup-lucid-memories/scripts/` 配下に完全集約・カプセル化する。本設計は特定要件・仕様の精緻化ではなくリポジトリ構成上の全体決定であるため、`scope: cross_cutting` として定義する。あわせて、スキル定義文書（`SKILL.md`）、利用ガイド（`SETUP_GUIDE.md`, `README.md`）、および単体テスト（`tests/test_setup.py`）の参照先を統一改訂する。

### Structure

1. **ディレクトリ構造**:
   ```text
   skills/setup-lucid-memories/
   ├── SKILL.md
   └── scripts/
       ├── setup.py   # Python 版メインセットアップロジック
       ├── setup.sh   # POSIX (macOS/Linux) 向けシェルランナー
       └── setup.ps1  # Windows (PowerShell) 向けランナー
   ```
2. **ルート特定ロジックの調整**:
   - `setup.py`: `Path(__file__).resolve().parents[2]` によりリポジトリルート（`lucid-memories/`）を算出する。
   - `setup.sh`: スクリプト位置から 3 階層上の絶対パスを算出（`$(cd "$(dirname "$0")/../../.." && pwd)`）。
   - `setup.ps1`: スクリプト位置から 3 階層上のパスを算出（`Split-Path -Parent (Split-Path -Parent (Split-Path -Parent $ScriptDir))`）。
3. **テスト構成**:
   - `tests/test_setup.py` でロードする対象スクリプトパスを `ROOT / "skills" / "setup-lucid-memories" / "scripts" / "setup.py"` へ更新する。

### Data Flow

1. AI エージェントが `setup-lucid-memories` スキルを参照し、`skills/setup-lucid-memories/scripts/setup.sh` または `.ps1`、`.py` を呼び出す。
2. スクリプトは自身の配置階層からリポジトリルートを割り出し、`sys.executable` を解決する。
3. `setup.py` のメイン処理が駆動され、依存解決、`.db/` および `persona/` ディレクトリ確認、MCP/フック設定のマージ、スキルのデプロイ、および検証を行う。

### Trade-offs

- **汎用 `scripts/` 配下配置 vs スキル内配置**:
  一般的なスクリプト置き場である `scripts/` に配置する案もあるが、セットアップ処理が Cursor エージェントの自律スキル（`setup-lucid-memories`）と強く結びついていること、およびスキル単位の自己完結型パッケージング（Agent Skills 標準規約）に準拠させる観点から、スキル内 `scripts/` サブディレクトリへの集約を採用した。
- **後方互換性**:
  ルート直下のスクリプトは削除されるため、過去のコマンドライン直接呼び出し（`./setup.sh` 等）はパスの変更（`./skills/setup-lucid-memories/scripts/setup.sh`）が必要となるが、`README.md` および `SETUP_GUIDE.md` の記述を更新することで利用者の混乱を防ぐ。
