## Content

### Decision

ダッシュボードおよびフロントエンド起動体験を最適化するため、`src/lucid_memories/web/dashboard.py` および `src/lucid_memories/entrypoints/cli.py` のコマンドライン引数解釈を拡張し、`open` サブコマンド／位置引数をネイティブに受理できるようにする。また、リポジトリ内 `bin/` 配下に `lg`, `lg.cmd`, `lucid-graph`, `lucid-graph.cmd`, `lucid-memories`, `lucid-memories.cmd` を配置し、ユーザーの `~/bin/` 環境と完全に一致する実行スクリプト群を提供する。

### Structure

1. **Python CLI層 (`src/lucid_memories/`)**:
   - `web/dashboard.py`:
     - 引数パーサーに位置引数 `action`（任意、`open` / `start` 等）を追加、または第1引数が `open` の場合に `--open`（`open_browser=True`）として扱うディスパッチロジックを実装。
   - `entrypoints/cli.py`:
     - `sub.add_parser("open", parents=[shared])`: `lucid-memories open` で即座にブラウザ起動付きでダッシュボードを開始。
     - `p_dashboard` に位置引数 `action` を追加し、`lucid-memories dashboard open` を解釈可能にする。
2. **スクリプト層 (`bin/` & `~/bin/`)**:
   - `bin/lg` & `bin/lg.cmd`:
     - `lucid-graph` / `lucid-graph.cmd` を透過的に呼び出すエイリアススクリプト。
   - `bin/lucid-graph` & `bin/lucid-graph.cmd`:
     - リポジトリルートを特定し、`PYTHONPATH="$ROOT/src"` を設定。
     - 引数 `$@` を `lucid_memories.web.dashboard` に渡す。
     - 引数が `open` の場合、`python -m lucid_memories.web.dashboard --open` が実行されるように正規化・中継。
   - `bin/lucid-memories` & `bin/lucid-memories.cmd`:
     - リポジトリの `src/lucid_memories/entrypoints/cli.py` を呼び出す。
3. **フロントエンド資産の配信方針**:
   - 旧単一HTML組み込みUI（`dashboard.html`）は一切使用せず、`src/lucid_memories/web/frontend/dist` 配下のビルド済みReact SPAアセットを静的ファイルとして配信。

### Data Flow

```text
[ユーザー入力: lg open]
        │
        ▼
[~/bin/lg -> ~/bin/lucid-graph]
        │
        ▼ (PYTHONPATH=.../src, 引数 "open" を "--open" へ中継)
[python -m lucid_memories.web.dashboard --open]
        │
        ├─► [ThreadingHTTPServer] (ポート 8765 で HTTP API & React dist 静的ファイル待受)
        └─► [webbrowser.open] (ブラウザで http://127.0.0.1:8765/ を自動起動)
```

### Trade-offs

- **スクリプト層での引数変換 vs Python層での柔軟なパース**:
  - スクリプト側で単純に中継するだけでなく、Python側（`dashboard.py`）でも `open` 位置引数を解釈可能にすることで、`python -m lucid_memories.web.dashboard open` や `lucid-memories dashboard open` などどの経路から実行しても一貫した動作を保証する。
- **組み込みUI（単一HTML）の非サポート維持**:
  - ReactフロントエンドをViteでビルドした静的成果物（`dist`）を配信するため、事前のビルドが必要となるが、コードベースの統合とデザイン品質（ダークテーマ、Sonner等）を維持し、二重管理の負債を避ける。
