## Content

### Decision

Cursor Hooks（一時プロセス）と MCP Server（常駐プロセス）が異なる実行環境で動作する構成において、SQLite 内の `session_bindings` テーブルを仲介させて最新のセッション識別子とワークスペース情報を共有する。

### Structure

- `entrypoints.hook`: Cursor IDEからの標準入出力イベントを受け取り、フック処理を実行するエントリーポイント。
- `entrypoints.mcp_server`: Cursor エージェントからの JSON-RPC (stdio) ツール呼び出しを処理する常駐サーバ。
- `session_bindings` テーブル: キー `mcp-current` に対する最新の `conversation_id`, `workspace_root`, `updated_at` を記録。

### Data Flow

1. ユーザーがプロンプト送信またはツール実行を行うと、Cursor IDE が `hook.py` を起動する。
2. `hook.py` は渡されたセッションIDとワークスペースを `session_bindings` の `mcp-current` に書き込む。
3. エージェントが MCP ツール（`whoami`, `status` 等）を実行すると、MCP Server はセッション引数が空の場合に `mcp-current` から現在セッションを特定する。
4. これにより、明示的なセッション引数が省略された場合でも両プロセス間で一貫したコンテキストが保持される。

### Trade-offs

- Cursorの制約によりHooksとMCPサーバを単一プロセスにまとめられない環境でもシームレスなセッション連携が可能となる。
- 同時に複数のウィンドウやセッションがアクティブである場合、`mcp-current` が上書きされる競合を避けるためワークスペース別バインディングの考慮が必要となる。
