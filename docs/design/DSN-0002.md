## Content

### Decision

リポジトリは、ドメイン、ユースケース、外部接続、画面表示、テストを責務別の領域に分けて構成する。

### Structure

- `domain`: 記憶と検索結果のドメインモデル
- `application`: 保存、検索などのユースケース
- `adapters`: SQLiteや外部サービスとの接続
- `presentation`: CLIやダッシュボードなどの表示
- `tests`: 各領域と領域間のテスト

### Data Flow

利用者の入力は `presentation` から `application` に渡り、`application` が `domain` と
`adapters` を組み合わせて処理し、結果を `presentation` に返す。

### Trade-offs

- 責務ごとの変更範囲を限定しやすくなる。
- 小規模な変更でも複数の領域を確認する必要があり、構成の理解に初期コストがかかる。

この設計は個別の要件・仕様を精緻化したものではなく、リポジトリ全体の構造を定める横断的な設計である。
