## Content

### Decision

エージェントのコンテキスト溢れを防止するため、ペルソナ注入やスナップショット復元において、文字数からトークン数を高速推定し、指定予算上限に達するまで優先度順に要素をパックする動的トリミング方式を採用する。

### Structure

- `runtime.util.estimate_tokens`: 英語・日本語・記号の出現傾向に応じた高速トークン数概算関数。
- `core.persona`: ルールの重要度に基づき優先ソートし、予算（8,000トークン等）を超えない最大集合を構築するビルダー。
- `core.api.reload_pack`: スナップショット内の最新状態、タスク、イベントを重要度順に結合し、予算（2,000トークン等）内で安全に切り詰めるローダー。

### Data Flow

1. 注入または復元要求時に許容トークン予算（`budget`）が渡される。
2. ビルダーが構成要素（ルール、コンテキスト行、サマリー）を優先度の高い順に走査する。
3. 要素を追加するごとに累積見積もりトークン数を計算し、予算上限を下回っているか確認する。
4. 予算上限を超過する要素は切り捨てまたは省略記号付きでトリミングし、最終テキストを組み立てて返却する。

### Trade-offs

- 高価なLLMトークナイザAPIを呼び出すことなく、ローカルかつミリ秒未満で安全なコンテキスト境界を強制できる。
- トークン見積もりは近似値であるため、実際のLLMトークナイザとのわずかな誤差（±5%程度）を見込んでマージンを設ける必要がある。
